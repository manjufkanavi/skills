oMLX Model Lifecycle Management

Creating a skill to programmatically unload and load models on Mac Studio

Press → or Space to navigate

Why Model Lifecycle Management?

  • 64GB unified memory constraint
  • MLX LLM and ComfyUI cannot run simultaneously
  • Need sequential unload/load cycle
  • Default model must be restored after generation

oMLX Architecture

  • Continuous batching — concurrent request handling
  • Paged KV cache — prefix sharing across requests
  • SSD prefix cache — hot/cold tiered storage
  • Multi-model residency — YAML config
  • OpenAI + Anthropic endpoints — unified API

Key API Endpoints

Unload
POST /v1/models/unload
Load
POST /v1/models/load
Status
GET /v1/status
List
GET /v1/models
curl -X POST http://localhost:8095/v1/models/unload \ -d '{"model":"mlx-community/Qwen3.6-35B-A3B-4bit"}'

Python Skill Implementation

#!/usr/bin/env python3 import requests OMLX_BASE = "http://localhost:8095" def unload_model(model_name): return requests.post( f"{OMLX_BASE}/v1/models/unload", json={"model": model_name} ).json() def load_model(model_name): return requests.post( f"{OMLX_BASE}/v1/models/load", json={"model": model_name} ).json() def swap_models(from_m, to_m, wait=10): unload_model(from_m) time.sleep(wait) return load_model(to_m)

Complete Workflow

  1. Check oMLX status
  2. Unload default LLM model
  3. Wait for unload (10s)
  4. Submit ComfyUI workflow
  5. Monitor via WebSocket
  6. Free ComfyUI memory
  7. Reload default LLM model
  8. Verify model is responding

Hermes Agent Integration

  • Define skill with tool descriptions
  • Agent auto-selects unload/load tools
  • Prompt template enforces lifecycle order
  • Verification step before/after each operation
tools: - name: omlx_unload parameters: { model: string } - name: omlx_load parameters: { model: string } - name: omlx_swap parameters: { from_model, to_model, wait }

Error Handling

  • Connection refused: Start oMLX server
  • Model not found: Verify path with `omlx list`
  • OOM during load: Use quantized model
  • Swap timeout: Increase wait time
  • API format error: Check JSON structure

Key Takeaways

  • oMLX provides explicit unload/load API for model lifecycle
  • Sequential cycle is mandatory on 64GB Mac Studio
  • Python skill with argparse enables CLI and agent use
  • WebSocket monitoring provides real-time progress
  • Multi-model YAML config enables advanced residency
