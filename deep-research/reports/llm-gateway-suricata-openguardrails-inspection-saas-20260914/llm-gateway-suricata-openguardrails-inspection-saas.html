The Gap

The Visibility Wedge

Every LLM call flows through a gateway, yet defense is split across two blind spots:

Network layer is blind to meaning

Suricata sees encrypted HTTPS carrying a chat.completions request. It cannot parse prompt intent, an embedded injection inside a doc, or whether a tool call is authorized.

Semantic layer is blind to transport

Guardrails inspect prompt text but live inside the app loop — they can't see if an agent's response is tunneled to a C2 server or how much left via covert egress.

A sophisticated indirect prompt-injection attack — malicious instructions buried in a document the agent reads, not sent by the user — slips through both.

Architecture

The Two-Layer Gateway

A · Suricata (Network)

  • DPI on raw HTTP/TLS/WebSocket
  • C2 / exfil tunnel detection
  • JA3/JA4 fingerprinting
  • EVE JSON → SIEM / block

B · OpenGuardrails (Semantic)

  • /v1/evaluate at request & response
  • GuardEvent → Verdict
  • Safety.* + Security.*
  • Fail-open by default

Converge Here

  • Cross-layer correlation
  • "Intent + egress" = high-confidence block
  • One audit trail

Suricata's network verdict feeds OpenGuardrails evaluation — e.g. "block this tool call because its response is destined for an exfiltration endpoint." This correlation exists in no single off-the-shelf tool.

Layer A

Suricata — Network Inspection (v8.0)

DPI + LALPs

8 new layer-7 protocols, 107 rule keywords, runtime plugin parsers. Principle: "if you log it, you can use it in a rule."

Fingerprinting

JA3/JA4 flags anomalous TLS clients — agent libraries masquerading as browsers, C2 beacons.

NFQUEUE IPS

Active inline drop of malicious flows, not just alerting.

Community proof — CGTI for OpenClaw: 646 active Suricata rules targeting MCP-SSRF, WebSocket tool-injection, AI-skill supply-chain poisoning. Dual-indicator minimum + 3 confidence layers + MITRE ATT&CK metadata.

Layer B

OpenGuardrails — Semantic Protocol (v0.8)

Apache-2.0, vendor-neutral protocol, not a product — "vendors compete behind one plug." One endpoint, two calls per model call:

step / request

Evaluated before the model runs — input guardrails (injection, jailbreak, PII).

step / response

Evaluated before the agent acts — output guardrails (exfil, policy violations).

Core Thesis

Suricata Sees the Channel · OGR Sees the Intent

Attack vectorSuricata (network)OGR (semantic)

Both agree (intent + egress) → high-confidence block, low false positives. They disagree → escalate to human review. Defense in depth at the transport/semantic seam.

Threat Model

The "Lethal Trifecta"

Data access

Agent can read private records / secrets.

Untrusted content

Agent reads documents it cannot fully trust.

Egress channel

Agent can send data out.

An agent with all three can be turned into a data-exfiltration tool by content it merely reads.

Direct injection

In user input — detectable.

Indirect injection

In retrieved docs — the dangerous one.

Tool-mediated

In tool metadata.

Blueprint

Reference Architecture — Per-Call Pipeline

1. Pre-model: OGR input + Suricata flow → 2. Model call (relayed, logged) → 3. Post-model: OGR output + Suricata egress
4. Pre-action: OGR tool-call semantics → 5. Suricata sees actual connection opened → 6. Cross-layer → single decision + audit

Four enforcement points — pre-model, post-model, tool-call, egress. Guardrails are probability filters; the gateway must ALSO enforce deterministic controls: least-privilege tools, typed interfaces, digest-pinned deploys.

Reality Check

Risks & Open Problems

Detection is never solved

Injection is semantic & an arms race. Position as risk reduction, not elimination.

Gateway is a prime target

2026 LiteLLM flaw: CVSS 8.7, EPSS ~80%, CISA KEV. Every path must audit.

Latency

Two layers per call must stay sub-100ms for agentic loops.

False positives break trust

Enterprise agents take real actions; over-blocking erodes adoption.
