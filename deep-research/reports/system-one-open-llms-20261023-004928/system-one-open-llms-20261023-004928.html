What is a System One model?

Kahneman's System 1, made into a model

Fast, automatic, intuitive judgment — from Thinking, Fast and Slow. TypeSafe AI (ex-OpenAI) launched Jev on 15 Sep 2026 as the first model in this category.

Give it a state (text/JSON) + typed questions → it returns calibrated probabilities: choice (≤255 options) · score (levels) · noul (yes/no).

No text is generated — one forward pass, zero structured-output errors. Jev: ~10 ms, 350+ RPS/1 vCPU, 64k context — but closed (proprietary RLCD, hosted API, undisclosed size).

How the open versions work

The decision is written as a sentence to complete; each option is scored as that completion at one token position, then normalised (temperature / head calibration).

Three open architectures:

  • LoRA + decision head on a frozen open LLM — JEV family, JevK5, Jev-Style, guards, OpenThai, Jeva
  • Contrastive heads on a frozen encoder — CLM-8B (up to 9× faster than Jev)
  • Encoder-only — von 395M (CPU, 1–2 GB), THX-01 322M (phone), open-jev-deberta

    • Why the open ecosystem exploded

    Jev's sweet spot is agent glue — routing, tool selection, moderation, RAG relevance, verification, computer-use. A closed API for that means cost, lock-in, and data egress. So the community rebuilt it:

    Families, in one breath

    JEV — AutoTrust

    "One decision model instead of a ranking team": frozen Qwen3.5/3.8 or Gemma-4 backbone + LoRA "Blocks of Experts" System-1 block (head seeded from lm_head, trained on Jev 1.13 distributions) + unmodified backbone as System 2, routed per request. Serves the Jev contract. 11 of the top-20 slots.

    JevK5 — alibiserikbay

    Single-file 4.2B on Qwen3.5-4B, CUDA-graph serving, ~13 ms/decision on H100. Best open model on JevBench v1.4: #2 of 76 (62.04 vs Jev 63.29).

    Jev-Style — chaoliangUNSW

    2B / 0.8B, GGUF + MLX builds, zero-cost calibration folded into the final RMSNorm. 77 ms per decision on an M1 Max; v3: 25.6K-token states, 51 languages, 77 options, no letter cap.

    OpenThai — iApp

    Thai + English 0.8B (Qwen3.5-0.8B continued on ~5B Thai tokens), 256-way slot head, TypeSafe-compatible API. Plays Doom: ~24 decisions/s on one H100.

    1.5B guards — JackKozmo29

    Dependency / mail / severity / code guards on Qwen2.5-1.5B — each faster locally than the hosted Jev API it replaces.

    Hardware & speed rules of thumb

    RAM ≈ params × bytes + ~15%

  • bf16 = 2 B/param · Q8 ≈ 1 B · Q4 ≈ 0.5 B
  • 0.5–1B (OpenThai, Tiny-Jev): 1–1.8 GB — any laptop / even phone
  • 1.5–4B (guards, JevK5, Jeva): 3–10 GB — a 16 GB Mac / 8 GB GPU
  • 8–9B (JEV-9B): 6–18 GB — 24 GB GPU for bf16 comfort
  • 26–36B (JEV-27B/35B): 27–72 GB — one B200 / 48 GB GPU, or NVFP4 ~27 GB
  • Heads-only repos (CLM 76 MB, mini-Jev) inherit the backbone's cost

    • One forward pass = prefill cost

    Latency scales with state length, not answer length.

  • Tiny / 0.5–1B: 10–50 ms (GPU or M-series)
  • 2–4B: 13–90 ms (H100/B200) · 77 ms (M1 Max)
  • 27B class: 80–400 ms (top GPU)

    • State caching is the multiplier: Jev-Style v3: 16.2 s cold → 0.17 s for the next question on the same 24.4K state. CLM reuses action embeddings: 13× faster than Jev at ~1k candidates.

    Challenges & honest caveats

    Calibration is still the moat

    Bekko v0 (the S1MB author's own): open models "fall far behind Jev 1.13 on S1MB benchmarks designed to measure generalization." Best open (JevK5) trails Jev by ~1.3 points on JevBench; hard tiers (adversarial, long docs) are where open models bleed.

    Is the category real?

    Univ. of Bonn's evaluation and the "glorified zero-shot classifier" critique: Jev may be a rebranded calibrated classifier. S1MB (100+ models, one harness) is the emerging neutral ground — use it, don't trust single-benchmark marketing.

    Long states are expensive

    24K-token decisions cost seconds even at 2B. The "fast" claim holds best at ≤4K tokens and with state reuse/caching.

    Ecosystem fragmentation

    287 projects, ~10 architectures, 4 wire contracts (Jev /v1/systemone is winning). Quality varies from phone-class 322M to 36B MoE — benchmark before you bet.

    Where this goes

    • MoE closes the cost gap: 26B-A4B / 35B-A3B put frontier-class decision fidelity on one 32–48 GB GPU at NVFP4.
    • The wire contract standardises: Ollama 0.35 + Ollaya serve open System One models behind the Jev API — drop-in replacement for hosted Jev.
    • Expect the open gap to close on standard benchmarks within ~a year; the durable open differentiators are on-prem data control, per-domain fine-tunes (guards, churn, domain NLI), and sub-10 ms tiny models in the request loop.
    • Practical picks today: 1.5B guards / 2B Jev-Style for edge & local agents · JevK5 4B for best open fidelity-per-second · JEV-9B on a 24 GB GPU to replace hosted Jev · JEV-27B/35B (NVFP4) where you need Jev-level depth.
    Key takeaways

    System One, open edition

    1. System One = state + typed questions → calibrated probabilities, one forward pass, no text. Jev (TypeSafe) defined it — and stayed closed.
    2. The open answer is the JEV family: 5 of the top 6 HF repos, Apache-2.0, 90–264 ms on top GPUs vs Jev's 238–301 ms hosted.
    3. Best open fidelity per second: JevK5 (4.2B, ~13 ms, #2 of 76 on JevBench); fastest class: 1.5B guards & 0.75B OpenThai under 100 ms on laptops.
    4. RAM budget: 1.5 GB (0.8B) → 6 GB (1.5B) → 8–18 GB (4–9B) → 27–72 GB (26–36B MoE); Q4/NVFP4 halves it.
    5. Check licenses: StartLux is NC, several repos ship unlicensed; Gemma bases keep Gemma terms. Benchmark on S1MB before deploying.
