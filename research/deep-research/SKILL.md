# Deep Research

## When to use

Use when the user asks for:
- "deep research on [topic]"
- "comprehensive research on [topic]"
- "research report about [topic]"
- "deep dive into [topic]"
- "thorough analysis of [topic]"

## How to run

```bash
python3 skills/deep-research/deep_research.py "your query here"
```

## Workflow

### Phase 1: General Search
1. Generates ~26 diverse search queries (overview, history, technical, comparisons, use cases, market, challenges, future)
2. Executes queries via Tiny Fish Search API
3. Deduplicates URLs from results
4. Scrapes content via Tiny Fish Fetch API in batches of 10
5. Iterative deepening: if fewer than 80 unique pages, generates follow-up queries from discovered content (up to 3 rounds)

### Phase 2: Research Site Searches
Searches 8 research sites: arXiv, Google Scholar, PubMed, Semantic Scholar, Nature, Science, IEEE Xplore, ACM Digital Library

### Phase 3: PDF Extraction
Discovers PDF URLs and extracts text using pypdf → pdfplumber → pdftotext (fallback chain)

### Phase 4: Report Generation (Agent-Done)

**IMPORTANT:** The `deep_research.py` script only handles search/scrape (Phases 1-3). It writes structured data to `research_data.json` but does NOT synthesize the markdown report.

After the script exits, the agent MUST:
1. **Verify data freshness** — `research_data.json` in the git repo may contain stale data from a *previous* run. Always check that `data.get('topic')` matches the current query before trusting the content. If the JSON is stale, re-run the script or skip to Phase 4 using whatever search results are available.
2. **Find the correct file locations** — the skill lives under `~/.hermes/skills/research/deep-research/` but the git repo may be under a different path (e.g., `~/.nanobot/workspace/git_clone_dir/personal_bot/skills/deep-research/`). Use `find` or `ls` to locate the actual `research_data.json` and report directories before proceeding.
3. Read the verified `research_data.json` to get scraped content
4. Synthesize a markdown report using the agent's own LLM
5. Write the `.md` report to the new report subdirectory
6. Generate the styled HTML report by rendering the markdown into the default template
7. Commit and push both files

**Default Template:** `03-heritage-essay.html` — the classic printed aesthetic with serif typography, Roman numeral sections, drop caps, and ornamental separators. This is the definitive template for all deep research reports.

The HTML slideshow IS auto-generated by the script — verify it exists. The `.md` report must be authored by the agent. The styled HTML report (from the heritage-essay template) is the final deliverable.

**Template rendering step:** After writing the `.md` report, use the bundled rendering script (`scripts/render_html.py <markdown_file>`) to generate the HTML report. It automatically finds the template, extracts the CSS, converts the markdown to properly styled HTML, and writes the output. If the script cannot locate the template, search in `~/.hermes/skills/research/deep-research/html_templates/03-heritage-essay.html` or the git clone path (`~/.nanobot/workspace/git_clone_dir/personal_bot/skills/deep-research/html_templates/03-heritage-essay.html`).

**Script execution pitfall:** When building the markdown-to-HTML converter manually (bypassing the script), NEVER use `\\uXXXX` escape sequences in Python regex replacement strings — Python's `re.sub()` with a raw string (`r'...'`) treats `\\u` as an invalid escape and raises `re.PatternError`. Instead, use `chr(10003)` for ✓ and `chr(9744)` for ☐. Also: the script uses `\\n\\n(.+?)\\n\\n` for paragraphs, so **avoid bare double-newlines in code blocks** — wrap code blocks in `<pre>` first before paragraph processing.

**Render script bug (fixed):** The bundled `scripts/render_html.py` has the same `\u` escape bug on lines 143-144. Patch: replace `r'<li class="task-done">\u2713 \1</li>'` with `r'<li class="task-done">' + chr(10003) + r' \1</li>'` and similarly for ☐ with `chr(9744)`.

- **Script execution pitfall:** Running `python3 deep_research.py` in the sandboxed background process produces no visible output for several minutes due to stdout buffering. If you need to observe progress, run from the terminal directly or use `python3 -u` for unbuffered output. If the script is running for more than 60 seconds without output, check `research_data.json` file modification time to see if data collection is still in progress.
- **Topic string too long → filename overflow:** The script generates the report directory name from the topic string. When the topic exceeds ~100 characters, the resulting filename can exceed the OS limit (255 chars on macOS), causing `OSError: [Errno 63] File name too long` at the HTML generation step — **even though data collection succeeded**. The `research_data.json` is still written. Fix: keep the topic query concise (under ~100 chars). If the script crashes here, the data is still in `research_data.json` — proceed to Phase 4 synthesis manually.

## Output

Each research run creates a **new subdirectory** under `skills/deep-research/reports/` named `<topic-slug>-<timestamp>` containing:
- **HTML slideshow** (auto-generated by script): `<topic-slug>-<timestamp>.html`
- **Markdown report** (agent-authored): `<topic-slug>.md` — the agent synthesizes this from `research_data.json`

Example:
```
reports/
  loop-engineering-ci-cd-20260710-053000/
    loop-engineering-ci-cd-20260710-053000.md
    loop-engineering-ci-cd-20260710-053000.html
```

### Mandatory post-generation steps
After the script finishes and you've authored the .md report:
1. **Commit and push** — run `git add`, `git commit -m "Add deep research report: <topic>"`, then `git push`.
2. **Delete old iterations** — remove previous report directories for the same topic (keep only the latest).
3. **Verify** — confirm both .md and .html exist in the new directory and the push succeeded.

## Technique: security / weapon-landscape research

For queries that resolve to a *catalogue of tools* (pen-testing suites, security CLI
tooling, survey lists like "best X tools in 2026"), the scraped corpus is almost always
**listicle-dominated** (blog roundups, forum threads, YouTube), plus a few authoritative
anchors (github `awesome-*` lists, OWASP). Do not concatenate sources. Instead extract the
actual tool names (recipe in `references/weapon-landscape-research.md`), curate them into
category-grouped tables, and rank by citation frequency. If the user only wants a summary,
deliver the table and skip the full HTML report.

## Constraints

- **Timeout**: 600s hard limit
- **Target**: ~80 unique pages per run
- **Report quality**: Concise, readable, 5-10 pages max (~8K chars) — never merge raw scraped sources
- **Deduplication**: Use `` tags during generation to facilitate duplicate removal
- **Text cleaning**: Aggressively strips YouTube metadata, Instagram boilerplate, Reddit headers, and creator names
- **PDF extraction**: IEEE Xplore and Semantic Scholar return HTML wrappers — extraction will fail on these sources
- **Retention**: Keep only the latest report per topic; delete previous iterations
- **Synthesis**: Use the agent's own LLM for report synthesis, NOT Tiny Fish API
- **New directory per run**: Every research creates a fresh `<topic-slug>-<timestamp>` subdirectory — never reuse or overwrite
- **Git commit + push mandatory**: After generating HTML and authoring the `.md`, always commit and push.

## Output Format

### Phase 1–3 Output: `research_data.json`

Structured JSON at `skills/deep-research/research_data.json` containing:
- `topics`: array of researched topics
- `themes`: identified thematic clusters
- `sources`: deduplicated source URLs with metadata

### Phase 4 Output: Synthesized Report

Uses the agent's own LLM to produce:
1. Executive Summary
2. Theme Sections (with evidence from sources)
3. References (top 30 sources)

Then generates:
- A markdown report (`.md`) with full research findings
- An HTML slideshow (`.html`) with responsive, animated presentation

Both files go into a new `<topic-slug>-<timestamp>` directory under `skills/deep-research/reports/`, then are committed and pushed to git.

## Tool Access Notes

- **Do NOT use shell `exec` to read `research_data.json`** — safety guards block access to `skills/` directory from exec sandbox. Use the `read_file` tool instead.
- Exec sandbox is restricted to workspace directory only.

## Dependencies

- `pypdf`, `pdfplumber`, `pdftotext` (poppler)

## Known Issues

- IEEE Xplore and Semantic Scholar consistently return HTML instead of binary PDFs
- Report generation must support thematic synthesis, not just concatenation

## Troubleshooting

- **Sandbox writes lost to git-tracked files**: `research_data.json` lives in a git-tracked directory (`~/.hermes/skills/research/deep-research/` OR `~/.nanobot/workspace/git_clone_dir/personal_bot/skills/deep-research/`). Writes inside the sandboxed background process don't propagate back to the original file. If the file is unchanged after the script exits, either run in foreground or regenerate content directly. See `references/deep-research-sandbox-pitfall.md` for full details.
- **Stale research_data.json**: Always verify `data.get('topic')` matches the current query. The JSON in the git repo may contain data from a *previous* run on a different topic.
- **Missing paths**: The skill lives under `~/.hermes/skills/research/deep-research/` but the git repo may be under `~/.nanobot/workspace/git_clone_dir/personal_bot/skills/deep-research/`. Use `find` to locate `research_data.json` before proceeding.
- **Script hangs silently**: `deep_research.py` buffers stdout in the sandbox. Check `research_data.json` file modification time to confirm data collection is in progress.
- **HTML templates are static**: `03-heritage-essay.html` is a plain HTML file, not a Jinja/templating file. Replace content using string replacement in the agent.
