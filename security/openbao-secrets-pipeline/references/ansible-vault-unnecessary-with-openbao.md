# Ansible Vault Unnecessary with OpenBao-First Architecture

## When Vault Is NOT Needed

If your docker-compose templates use:
- **`{{ variable_name }}`** — from `defaults/main.yml` (unencrypted, lifecycle/config values)
- **`${ENV_VAR}`** — from `.env` at runtime (sourced from OpenBao KV)

Then the Ansible vault is **not needed** for service credentials.

### Template Pattern

```yaml
# docker-compose.yml.j2
services:
  postgres:
    environment:
      POSTGRES_PASSWORD: "${POSTGRES_PASSWORD}"    # From .env → OpenBao KV
    deploy:
      resources:
        limits:
          memory: "{{ service_memory_defaults.postgres }}"  # From defaults/main.yml
```

No Ansible variable reference = no vault needed.

## When Vault WAS Used (Old Pattern)

The old pattern stored passwords in `inventory/group_vars/all.yml` (vault-encrypted) and referenced them in templates:
```yaml
environment:
  POSTGRES_PASSWORD: "{{ postgres_password }}"  # Requires vault
```

This is **deprecated** in favor of the OpenBao-first approach. All credentials should be generated by OpenBao and injected via `.env` at container bootstrap.

## How to Migrate

1. Replace all `"{{ var_name }}"` references with `"${ENV_VAR}"` in templates
2. Remove `vault_password_file` from `ansible.cfg`
3. Convert `inventory/group_vars/all.yml` to unencrypted (keep non-secret config only)
4. Remove vault-encrypted files

## Diagnostic

```bash
# Check if templates reference any ansible variables for passwords
grep -rE '\{\{[[:space:]]+[A-Z_]+\}' roles/*/templates/*.j2 | grep -i pass

# Check if ansible.cfg requires a vault
grep 'vault_password_file' ansible.cfg
```
