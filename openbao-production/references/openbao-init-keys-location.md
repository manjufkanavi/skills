# Multiple init_keys.json — Key Mismatch Diagnostic

## Problem

When unsealing fails with `"unable to retrieve stored keys: invalid key: failed to decrypt keys from storage: cipher: message authentication failed"`, the unseal keys in the `init_keys.json` being used do not match the seal wrapping key stored in the raft data. This often happens because **multiple `init_keys.json` files exist on the same VM with different key sets**, and the backup script or bootstrap script reads from the wrong one.

## IacGenie VM Layout (192.168.0.118)

This VM has THREE separate `init_keys.json` files, each with a different unseal key set:

| Path | Unseal Keys (first char) | Status |
|------|--------------------------|--------|
| `/home/mkanavi/docker/iacgenie/init_keys.json` | `WM3H...` | ✅ **CURRENT — works for unsealing** |
| `/home/mkanavi/docker/iacgenie/data/openbao_raft/init_keys.json` | `WM3H...` | ✅ **CURRENT — same set, mounted into container** |
| `/home/mkanavi/docker/iacgenie/openbao_raft/init_keys.json` | `Ji1h...` | ❌ **STALE — does NOT match current raft data** |

The backup script (`backup_openbao.py`) reads from `RAFT_DIR = /home/mkanavi/docker/iacgenie/openbao_raft/`, which points to the stale keys file. The Docker compose mount uses `data/openbao_raft` (the working keys). The top-level `init_keys.json` was generated by a later re-initialization.

## Diagnostic Procedure

When unsealing fails, check all init_keys.json files:

```bash
# List all init_keys.json files and their keys
for f in $(find /home/mkanavi/docker/iacgenie -name 'init_keys.json' 2>/dev/null); do
    echo "=== $f ==="
    python3 -c "
import json
d = json.load(open('$f'))
keys = d.get('unseal_keys_b64', [])
for i, k in enumerate(keys):
    print(f'  [{i}]: {k[:8]}... ({len(k)} chars)')
"
done
```

## How to Determine the Correct Keys

1. The keys that are **mounted into the container** at `/openbao/raft` are the authoritative set — they match the seal wrapping key in the raft data.
2. Compare key prefixes across files. The file(s) sharing the same key prefix are the working set.
3. If ALL key sets fail, the raft data may have been re-initialized. See Workflow B (Reinitializing) in `openbao-production/SKILL.md`.

## Prevention

- When re-initializing OpenBao, ALWAYS update ALL copies of `init_keys.json` on the VM.
- Document which path the backup script reads from vs. which path Docker mounts.
- Consider a symlink or single canonical location to avoid drift.
