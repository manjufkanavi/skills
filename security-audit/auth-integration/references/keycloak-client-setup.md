# Keycloak Client Setup — Configuration Checklist

## 1. Create/Update OIDC Client in Keycloak Admin Console

Navigate to: Clients → Your client (e.g., `resume-platform`) or Create Client.

### Required Settings
| Setting | Value | Notes |
|---------|-------|-------|
| Client ID | `resume-platform` (or your platform name) | Must match env var KEYCLOAK_CLIENT_ID |
| Client Type | OpenID Connect | Standard OIDC client |  
| Access Type | `confidential` | Backend needs secret. Use `public` only for SPA-only clients with no backend API calls |
| Standard Flow Enabled | ✅ ON | Required for Authorization Code + PKCE flow (SPA/Next.js)
| Direct Access Grants Enabled | ❌ OFF | Disable if using auth-wrapper (no ROPC). Enable only for backend-only clients that call `/token` directly with username/password |
| Implicit Flow Enabled | ❌ OFF (unless needed) | Only enable if you need `response_type=token` for token-only flows |
| Authorization Enabled | ❌ OFF (default) | Enable only if using Keycloak's authorization services (fine-grained permissions)

### PKCE Configuration
| Setting | Value | Notes |
|---------|-------|-------|  
| PKCE Code Challenge Method | `S256` | SHA-256 is the recommended method; plain only for legacy clients

### Redirect URIs
Add ALL of these (for both production and dev):  
- `https://resume.iacgenie.com/auth/callback` (production)
- `http://localhost:3006/auth/callback` (local dev, match your Next.js port)
- `http://127.0.0.1:3006/auth/callback` (alternative localhost)
- `http://localhost:*/*` and `http://127.0.0.1:*/auth/callback` (wildcards for multiple ports)

### Post Logout Redirect URIs
- `https://resume.iacgenie.com/login` (production)  
- `http://localhost:3006/login` (local dev)
- `*` (allow any — safer for development, restrict in production)

### Additional Settings
| Setting | Recommended Value | Notes |
|---------|-------------------|-------|
| Base URL | `https://resume.iacgenie.com/` (or dev equivalent) | Keycloak uses this for links in emails, etc.  
| Home URL | `https://resume.iacgenie.com/` (or dev equivalent) | Where to redirect after login if no return URL provided
| Web Origins | `+https://resume.iacgenie.com`, `http://localhost:3006` | For CORS — needed if frontend makes direct Keycloak calls
| Consent Screen Required | ❌ OFF (unless you need user consent flow) | For internal platforms, skip the consent screen

### Save and Record
After creating/updating: go to **Credentials** tab → copy the `Client secret` value. This must be stored in your platform's environment:
```bash
KEYCLOAK_CLIENT_SECRET=<paste-secret-here>
```

## 2. Verify Client Configuration

Test with curl (replace values as needed):

### Test: Exchange Authorization Code for Token
```bash  
# Step 1: Get authorization URL (includes PKCE code_verifier in cookie)
curl -v "https://keycloak.iacgenie.com/realms/iacgenie/protocol/openid-connect/auth?client_id=resume-platform&response_type=code&redirect_uri=https://resume.iacgenie.com/auth/callback"

# Step 2: After user authorizes, Keycloak redirects with code=XXX
# Exchange the code for tokens:
curl -X POST "https://keycloak.iacgenie.com/realms/iacgenie/protocol/openid-connect/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code" \
  -d "client_id=resume-platform" \
  -d "redirect_uri=https://resume.iacgenie.com/auth/callback" \
  -d "code=<CODE_FROM_REDIRECT>" \  
  --data-urlencode "client_secret=<YOUR_CLIENT_SECRET>"
```

### Test: Introspect a Token (verify it's active)
```bash
curl -X POST "https://keycloak.iacgenie.com/realms/iacgenie/protocol/openid-connect/token/introspect" \
  -d "token=<ACCESS_TOKEN>" \
  --data-urlencode "client_secret=<YOUR_CLIENT_SECRET>" \
  -d "client_id=resume-platform"

# Expected response: {"active":true, ...}
```

## 3. Common Pitfalls

### Redirect URI Mismatch  
The redirect_uri in the authorization request MUST exactly match one of the configured URIs (including trailing slash). A mismatch causes Keycloak to reject with:
```
redirect_uri_mismatch - The redirect URI provided does not match the client's configured URIs.
```

### PKCE Code Verifier Not Stored
The code_verifier generated by the frontend must be stored (e.g., in an httpOnly cookie) and sent during token exchange. If the frontend generates code_challenge but doesn't store code_verifier, the token exchange will fail with:
```  
invalid_grant - PKCE verification failed. The code_verifier does not match the original challenge.
```

### Direct Access Grants Left On  
If `Direct Access Grants Enabled` is ON while using auth-wrapper, users might accidentally use ROPC (username/password to `/token` endpoint) instead of the PKCE flow. This bypasses SSO and MFA requirements. Always disable it when using auth-wrapper or a dedicated credential proxy service.

### Missing Web Origins for CORS
If the frontend needs to make direct API calls to Keycloak (e.g., getting user profile), Web Origins must include the frontend's origin. Otherwise, browser CORS preflight will block the request with:
```
Access to XMLHttpRequest at 'https://keycloak.../userinfo' from origin 'http://localhost:3006' has been blocked by CORS policy
```
